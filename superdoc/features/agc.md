# Better AGC (whole-stream leveler / compressor / limiter)

First mod. Runs a dynamics chain on **everything the client plays** (all speakers and sounds mixed),
configured from a "Mods" page in the client's Settings. Built from three parts: a native preload
module, a DSP core, and an injected UI panel ([mods-panel.md](mods-panel.md)).

Related: [architecture overview](../architecture/overview.md), [ts6-modding-surface.md](ts6-modding-surface.md) (launch/attach, stock AGC controls),
[ts6-ui-extension-points.md](ts6-ui-extension-points.md) (how the panel hooks into the UI),
[mods-panel.md](mods-panel.md) (panel + Dashboard button).

Tested on client `6.0.0beta5` and `6.0.0beta5.1` (Linux, PipeWire with the Pulse compatibility layer).

## Start it

```
launcher/ts6-mod [client args]            # same as the desktop entry plus the mod; close a running client first
```
Needs Node >= 22 and a C compiler (builds `native/libts6mod.so` on first start). Env: `TS6MOD_TS_BIN`
(client binary, default `/opt/teamspeak/TeamSpeak`), `TS6MOD_CDP_PORT` (debug port, default 9222, loopback),
`TS6MOD_PORT` (control API, default 38998, loopback), `TS6MOD_WRAP` (command prefix).
`launcher/ts6-mod.desktop` is a template for a menu entry: replace `<repo>` with the checkout path and copy it to
`$XDG_DATA_HOME/applications/` (not installed automatically). Closing the client ends the launcher.

## Vanilla guarantee (decision: everything is configurable)

- Every feature has its own switch and **defaults to off** (no config file = disabled).
- AGC off: the original `pa_stream_write` call is made with the untouched buffer. Bit-exact (verified by
  `native/test/run_hook_test.sh`), no delay, no allocation, no DSP call.
- Injected UI with everything off: only the "Mods" entry in Settings. The panel makes no request until needed; it
  never touches the client's own settings unless you flip the stock-AGC toggles on its page.
- No server traffic is ever generated by the mod. The client's own audio settings are only written when you use
  the two stock toggles on the Mods page.
- Without the launcher the client is vanilla (the module is just not loaded).

## Architecture

```
TeamSpeak main process
  libts6mod.so (LD_PRELOAD)           native/ts6mod.c
    dlsym() interposition  ->  wrappers for pa_stream_{connect_playback,write,write_ext_free,begin_write,cancel_write,disconnect}
    write wrapper          ->  ts6dsp (native/dsp): leveler -> compressor -> lookahead limiter, one state per playback stream
    control thread         ->  HTTP on 127.0.0.1:<port>: /config /status /meters   (+ config file)
launcher/ts6-mod -> tools/cdp/mods-inject.mjs  --CDP-->  UI page: panel/panel.js (Mods page)
                         ^ HTTP proxy for the panel (binding ts6modNative)
```

Hook mechanism (verified live on `6.0.0beta5` and again on `6.0.0beta5.1`; no offsets or minified names are used on the audio side): libpulse is `dlopen`ed and every function is resolved through
`dlsym(handle, name)`; the client resolves the whole `pa_stream_*` API plus the `pw_*` API (a PipeWire backend
exists but the live output stream was a PulseAudio one). Only symbols below are replaced; everything else gets the real pointer:
`pa_stream_connect_playback` (registers the stream, reads its sample spec), `pa_stream_write` and
`pa_stream_write_ext_free` (process), `pa_stream_begin_write`/`pa_stream_cancel_write` (zero-copy buffers are processed
in place), `pa_stream_disconnect` (unregisters). `pa_stream_connect_record` is never wrapped: capture is untouched.
Supported formats: `s16le`, `f32le`; anything else is passed through and shown as `unsupported` in `/status`.
Other `snd_pcm_*`/`pw_*` backends are **not** hooked (if the user selects the ALSA or PipeWire backend in the client the
mod has no effect).

Process model: on `6.0.0beta5` the client started, then re-spawned itself once (the second process is the real main process;
on `beta5.1` one process was observed), and CEF children (`--type=...`) inherit `LD_PRELOAD`. The module acts only if `/proc/self/exe` is the client binary
and the cmdline has no `--type=`; everywhere else `dlsym` is a plain forward (a tail call, so glibc still sees the real
caller for `RTLD_NEXT`). The control thread retries its port bind for a minute because the first process briefly holds it.

Audio path rules: no allocation, no locks. Per stream the module preallocates a 1 MiB copy buffer at connect time
(`write` input is `const`: copy, process, hand pulse the copy with a NULL free callback, call the original free
callback ourselves). Writes larger than that pass through unprocessed (`oversize` counter). Parameter changes go to the
DSP through its seqlock; a changed lookahead or an enable creates a new DSP state on the control thread and swaps it in
atomically; the old state is freed 3 s later. Toggling AGC on/off can click once (the delay line starts empty).
Enabling adds `lookahead_ms` of delay to **all** playback (default 5 ms; 0 = no delay, hard limiter).

## Control API (loopback only, `TS6MOD_PORT`)

| Request | Result |
|---|---|
| `GET /status` | `{module,version,pid,enabled,mode:"passthrough"\|"processing",config_file,hooked:[symbols],streams:[{format,rate,channels,processing,latency_frames,writes,processed_writes,passthrough_writes,oversize}]}` |
| `GET /config` | current config (below) |
| `POST /config` | JSON with any subset of the keys; clamped to the DSP ranges, applied live, saved; answers with the full config |
| `GET /meters` | `{active,in_db,gain_reduction_db,leveler_gain_db,in_peak_db,out_peak_db}`; the two peaks are sample peaks since the previous read and are only measured while processing |

Config keys: `enabled` (bool, default false), `dashboard_button` (bool, default false; UI switch, see
[mods-panel.md](mods-panel.md)), `preset` (name), `strength` (0-100), plus the `ts6dsp` parameters `target_db`,
`max_gain_db`, `gate_db`, `threshold_db`, `ratio`, `knee_db`, `attack_ms`, `release_ms`, `makeup_db`, `lookahead_ms`,
`ceiling_db` (ranges and defaults: [native/dsp/README.md](../../native/dsp/README.md)). Persisted to
`$XDG_CONFIG_HOME/ts6-mods/agc.json` (fallback `$HOME/.config/...`). Log: `$XDG_STATE_HOME/ts6-mods/ts6mod.log`
(which streams were hooked, which symbols the client resolved, errors).
Requests with an `Origin` other than `tsui://...` or a `Host` other than loopback are refused (a web page in a browser
cannot reach it).

## Panel (Settings -> Mods)

"Better AGC" switch, Gentle/Balanced/Strong presets and a Strength slider (piecewise-linear interpolation between three
parameter sets: `paramsForStrength` in `panel/panel.js`), advanced fields for every DSP parameter, live meters (polled only while the page is
visible), plus the client's stock **Automatic Gain Control** toggle for the active playback device and the hidden
**Experimental AGC mode** toggle (on `beta5.1` flipping it did not reopen the playback stream; mechanics in [ts6-modding-surface.md](ts6-modding-surface.md)). With the native module
absent the page says so and the two stock toggles still work.

## Known limits

- Whole stream only: all speakers share one gain. Per-speaker leveling needs a hook inside the client's mixer (a static
  per-speaker site exists in the binary; out of scope).
- Pulse backend only (see above). Updating the client may change how libpulse is loaded; re-check
  `ts6mod.log` for the `dlsym resolved` lines and the `playback stream` line after an update.
- Sound volume applied by the OS stream (sink-input volume) comes after our processing; wave-file sounds are mixed
  into the same stream but 20 dB lower (notification level), so they sit far below the limiter.
- Toggle click, 1 MiB buffer limit, `lookahead_ms` only applied on (re)create.
- The panel reaches the module through the CDP injector; if the injector process dies the page shows "not loaded"
  while audio keeps working with the last saved config.

## Tests

- `make -C native/dsp test`: DSP self-test (ceiling never exceeded at lookahead 0/5/20 ms).
- `native/test/run_hook_test.sh`: a stand-in client `dlopen`s libpulse and plays a burst signal to a temporary null
  sink under the preload; recorded from the sink monitor. Checks bit-exact passthrough before enabling and after
  disabling, and the peak ceiling while enabled.

## Why

- **dlsym interposition:** libpulse is `dlopen`ed, so a plain preload definition of `pa_stream_write` is bypassed;
  returning wrappers from `dlsym` is the only point that sees every lookup. `RTLD_NEXT` lookups are forwarded by tail
  call so interposers elsewhere keep working.
- **Hook at `pa_stream_write` (not the DSP inside the client):** the client's mixer and the stock WebRTC AGC are inside
  a stripped, statically linked core. The output write is the last point before the OS and needs no offsets, so it
  survives client updates as long as libpulse is used.
- **CDP + injected JS:** the stock binary verifies its UI bundle, so edited UI files are rejected; one extra launch flag
  (loopback only) lets us add UI without patching anything.
- **A CDP binding as the page's route to the module:** the stock UI page cannot open `http://` connections at all
  (`net::ERR_UNKNOWN_URL_SCHEME`, also for WebSocket/XHR/images), so the injector proxies the three endpoints via
  `Runtime.addBinding`. Side effect: the page is a thin client of the loopback API and the injector must keep running.
- **Default off:** the user's rule is that a client with everything disabled behaves like vanilla.
- **Switches in the module's config file, not the client's store:** the audio hook must obey them at start-up, before any
  UI exists, and the client's own profile stays untouched (deleting the `ts6-mods` config dir restores vanilla).
- **Unsetting nothing in `LD_PRELOAD`:** the first client process re-spawns itself; dropping the variable there would lose
  the mod entirely. The `--type=` filter is the guard instead.
- **Whole-stream compressor/limiter chain:** see [native/dsp/README.md](../../native/dsp/README.md) (slow leveler first,
  limiter last because only it can promise a ceiling).
- **Loopback listener hardening:** Origin/Host checks because any web page can otherwise fire requests at loopback.
