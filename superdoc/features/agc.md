# Audio mod: AGC (whole stream / per speaker) and per-user audio

Dynamics processing (leveler -> optional compressor, off by default -> lookahead limiter) on the voices the client plays, plus per-user volume,
mute, boost and AGC overrides. Built from four parts: a native preload module (`native/`), the DSP core
(`native/dsp`), an inline hook for per-speaker mode ([per-speaker-hook.md](per-speaker-hook.md)) and the injected `audio`
mod (`panel/mods/audio/`, TeamSpeak names in `panel/core/x-audio.js`; framework: [ts6-mod-api.md](ts6-mod-api.md)).

Related: [ts6-native-agc.md](ts6-native-agc.md) (how the stock playback AGC and its experimental mode behave, measured), [architecture overview](../architecture/overview.md), [ts6-modding-surface.md](ts6-modding-surface.md) (launch/attach, stock AGC
controls), [ts6-ui-extension-points.md](ts6-ui-extension-points.md), [mods-panel.md](mods-panel.md) (the Mods page),
[test-rig.md](test-rig.md) (known talkers, recording). Tested on client `6.0.0-beta5.1` (Linux, PipeWire with the Pulse layer).

## Start it

```
launcher/ts6-mod [client args]            # same as the desktop entry plus the mods; close a running client first
```
Needs Node >= 22 and a C compiler (builds `native/libts6mod.so` on first start). Env: `TS6MOD_TS_BIN`, `TS6MOD_CDP_PORT` (default 9222),
`TS6MOD_PORT` (control API, default 38998, loopback), `TS6MOD_PROFILE_DIR`, `TS6MOD_WRAP`: table in [ts6-mod-api.md](ts6-mod-api.md)
("Launcher"). Closing the client ends the launcher. Settings -> Mods -> "Audio" card.

## Modes

| mode (`mode`) | where it runs | notes |
|---|---|---|
| `whole` | `pa_stream_write` of the playback stream: one chain on everything mixed (voices + sounds) | works on any client; one loud speaker lowers the others |
| `per_speaker` (default) | inline hook on each sender's decoded PCM before the mix ([per-speaker-hook.md](per-speaker-hook.md)) | one chain per speaker, per-user overrides work, all speakers share one `lookahead_ms` delay; the whole-stream path then passes through |

**Ceiling in per-speaker mode:** the ceiling is applied to each speaker *before* the mix, so simultaneous speakers can sum above it
(measured: ceiling -6 dB, two talkers at once -> mixed peak -4.9 dBFS; the same run in whole-stream mode peaked at -6.0). Whole-stream mode
is the one that guarantees the ceiling on the final mix; if you need both (per-user control and a hard mix ceiling), combine them
(per-speaker levelling plus a whole-stream limiter) rather than relying on the per-speaker ceiling alone.

Per-user overrides (boost, bypass, custom AGC) only act in `per_speaker` mode with the AGC dropdown on TS6Mods. The hook is installed
the first time per-speaker mode is switched on with TS6Mods and stays installed (inactive = pure passthrough).

## Vanilla rule (decision D7)

Everything off = vanilla client: AGC off means the original `pa_stream_write` receives the untouched buffer (bit-exact, no delay,
no allocation; `native/test/run_hook_test.sh`), the per-speaker detour is passthrough, no file is patched. Without the launcher the
client is vanilla (module not loaded). No server traffic is ever generated by the mods (per-user settings are local).

**The mod switch also switches the native AGC.** The native `enabled` value lives in the native config (`agc.json`) because the audio
hook needs it at client start, before any UI exists. The rule that ties it to the mod:

- `panel/mods/audio/index.js:enable`: reads native `/config`; the user's own AGC choice is kept in the mod's storage (`agcMode`: `ts6mods` | `vanilla` | `experimental`) and pushed to
  the native module (`POST /config {enabled: choice === 'ts6mods'}`); the stock keys are applied too (below).
- `disable()` (switch off): restores the stock AGC values (below), then `POST {enabled:false}`; the native module persists it, so the next
  client start is vanilla even before any UI loads. It also restores everything done to users (below).
- Mod off at client start while a (legacy) native config still says `enabled:true`: nothing of the mod runs, so
  `panel/core/x-audio.js:vanillaGuard` (a core file, loaded regardless of the switch) does one `GET /config` and, if enabled, one
  `POST {enabled:false}` after the core started. Once per page load; nothing else is polled.
- Mod on again: the stored `agcMode` is applied again (native `enabled` and the stock keys).

### The AGC dropdown and the stock playback AGC

The Processing tab's first box "AGC" is a dropdown (`select[data-act=agc]`, styled with `--mods-field-*` tokens; the kit has no select) with
exactly three choices. It replaces the old "Audio processing (AGC)" on/off switch and the Per-user tab's two stock toggles.

| Choice | native `enabled` | stock `agc` | stock `agcExperimentalMode` |
|---|---|---|---|
| TS6Mods (default) | true | false | false |
| Vanilla | false | true | false |
| Vanilla (Experimental) | false | true | true |

Why: our leveler on top of the stock one makes two levelers chase each other ([ts6-native-agc.md](ts6-native-agc.md)), so TS6Mods turns
the stock one off. Experimental is only a modifier of the stock AGC (with `agc` off it does nothing, measured), so "Vanilla
(Experimental)" must switch the normal AGC on too.

- Setters: `panel/core/x-audio.js:stockAgc` (`api.stockAgc.read()` / `.write({agc, experimental, device})`) uses the stock settings model:
  `audioSettings.onAudioDspSettingsChanged({io:0, settings:{mode, deviceId, agc}})` for `agc` (what the stock Playback toggle calls; per output
  device) and `audioSettings[0].global.agcExperimentalMode` + `audio.Update()` on every connection for the flag, then `save()` (persists
  like a user change; the stock Settings toggle and the hidden dev card show the same state). Only changed values are written (the flag
  reopens the playback stream: short glitch).
- `agc` is per output device: the value is set for the active device, and a 3 s watcher re-applies it when the active device changes or the
  client connects after the mod was enabled. Other devices keep their own value (until selected).
- **Vanilla rule (D7)**: the first time the mod is about to change a stock value it stores the user's own value in `stockOrig`
  (`{agc: {deviceId: bool}, exp: bool}`, mod storage). `disable()` writes these back (per device, then the flag) and deletes `stockOrig`,
  so a switched-off mod leaves the stock settings as the user had them. The Vanilla choices write their values explicitly (the user's choice
  while the mod is on). If the settings model is unreachable at disable time (no connection) `stockOrig` is kept and retried at the next
  enable/disable. If the client is closed with the mod on, the written values persist (the mod being off at the next start does not undo them).
- If the user flips the stock toggle by hand while the mod is on, nothing fights it; the box shows the live stock state under the dropdown.
- Migration: the old stored `master` becomes `agcMode` on the first enable (true/absent -> TS6Mods, false -> Vanilla), then `master` is
  removed. The choice is applied on every enable, so an existing user's stock values are touched when the mod is next enabled (their
  originals are remembered first), not before.
- The card summary (`statusBits`) shows "Vanilla AGC" / "Vanilla AGC (experimental)" for the Vanilla choices, else "Per speaker · Voice ...".

Why: a second AGC-ish switch that stays on after the mod is off would silently process audio of a "vanilla" client; mod switch =
feature switch is the least surprising rule and needs no extra UI. Verified live: off -> `/status` passthrough, `added_latency_ms` 0;
reload with mod off and native on -> native turned off; on -> choice restored.

## Architecture

```
TeamSpeak main process
  libts6mod.so (LD_PRELOAD)           native/ts6mod.c
    dlsym() interposition  ->  wrappers for pa_stream_{connect_playback,write,write_ext_free,begin_write,cancel_write,disconnect}
    write wrapper (mode whole)        ->  ts6dsp (native/dsp): leveler -> compressor (only if `comp_enabled`) -> lookahead limiter, one state per playback stream
    inline hook (mode per_speaker)    ->  native/ts6hook.c: one ts6dsp per sender (pool of 32), overrides per clientId
    control thread         ->  HTTP on 127.0.0.1:<port>: /config /status /meters /speakers /speaker   (+ agc.json)
launcher/ts6-mod -> tools/cdp/mods-inject.mjs  --CDP-->  UI page: panel/core + panel/mods/audio
                         ^ HTTP proxy for the page (binding ts6modNative; allowed paths: /config /status /meters /speakers /speaker)
```

Whole-stream hook mechanism (verified on `6.0.0beta5` and `6.0.0-beta5.1`; no offsets or minified names on the audio side): libpulse is
`dlopen`ed and every function is resolved through `dlsym(handle, name)`; only these are replaced: `pa_stream_connect_playback`
(registers the stream), `pa_stream_write` and `pa_stream_write_ext_free` (process), `pa_stream_begin_write`/`pa_stream_cancel_write`
(zero-copy buffers processed in place), `pa_stream_disconnect`. `pa_stream_connect_record` is never wrapped: capture is untouched.
Formats `s16le`, `f32le`; others pass through (`unsupported` in `/status`). The ALSA and PipeWire backends are not hooked.

Process model: the client re-spawns itself once on some builds and CEF children inherit `LD_PRELOAD`; the module acts only if
`/proc/self/exe` is the client binary and the command line has no `--type=`. The control thread retries its port bind for a minute.

Audio path rules: no allocation, no locks. Per stream a 1 MiB copy buffer is preallocated at connect (writes larger than that pass
through, `oversize` counter). Parameter changes go through the DSP seqlock; a changed `lookahead_ms` or an enable creates a new DSP
state on the control thread and swaps it in atomically (old one freed 3 s later). Toggling can click once. Enabling adds `lookahead_ms`
of delay to **all** playback (default 5 ms; 0 = hard limiter, no delay).

## Control API (loopback only, `TS6MOD_PORT`)

| Request | Result |
|---|---|
| `GET /status` | `{module,version,pid,enabled,mode:"passthrough"\|"processing",config_mode,per_speaker:{hook_installed,hook_addr,active,speakers,added_latency_ms},config_file,hooked:[symbols],streams:[{format,rate,channels,processing,latency_frames,writes,processed_writes,passthrough_writes,oversize}]}` |
| `GET /config` | current config (below) |
| `POST /config` | JSON with any subset of the keys; clamped to the DSP ranges, applied live, saved; answers with the full config. A `preset` value may contain only letters, digits, `_` and `-` (anything else is ignored) |
| `GET /meters` | `{active,in_db,gain_reduction_db,leveler_gain_db,in_peak_db,out_peak_db}` (whole mode; peaks are sample peaks since the previous read, measured only while processing) |
| `GET /speakers` | per-speaker mode: `[{client_id,schid,active,frames,rate,channels,in_db,gain_reduction_db,leveler_gain_db,out_peak_db,override}]`. **`schid` is always 0** (the hook only knows the numeric client id), so the UI matches users by client id alone (ambiguous only with several simultaneous connections that hand out the same id) |
| `POST /speaker` | `{client_id, schid?, override:{enabled?,gain_db?,params?:{subset, not lookahead_ms}} \| null}`; `gain_db` is applied after the DSP and clamped to the ceiling; `enabled:false` = passthrough (with `gain_db`: plain gain, clamped to full scale); `null` clears. Overrides live per session and clientId; one for a client that is not talking yet applies on its first block |

Config keys: `enabled` (bool, default false; the mod drives it, see the vanilla rule), `mode` (`whole`\|`per_speaker`), `preset` (name; the
mod writes `voice`, `music`, `quiet`, `user_<id>` or `custom`; legacy values such as `balanced` are shown as "custom"), `strength`
(0-100, legacy, ignored by the mod), plus the `ts6dsp` parameters `target_db`, `max_gain_db`, `gate_db`, `comp_enabled` (bool, default false: compressor stage bypassed, see "Compressor switch"), `threshold_db`, `ratio`,
`knee_db`, `attack_ms`, `release_ms`, `makeup_db`, `lookahead_ms`, `ceiling_db` (ranges/defaults: [native/dsp/README.md](../../native/dsp/README.md)).
(`dashboard_button` is gone from the native config; the Dashboard button is its own mod, see [mods-panel.md](mods-panel.md).)
Persisted to `$XDG_CONFIG_HOME/ts6-mods/agc.json` (fallback `$HOME/.config/...`); log `$XDG_STATE_HOME/ts6-mods/ts6mod.log`.
Requests with an `Origin` other than `tsui://...` or a `Host` other than loopback are refused.

## The AGC page (Settings -> Mods -> Audio)

Code: `panel/mods/audio/index.js:settings`. Edits apply live (150 ms debounce, only changed keys) and are saved by the native module,
so they survive a client restart.

Layout (the Mods page frame is in [mods-panel.md](mods-panel.md)): four tabs (`api.ui.tabs`) of boxes. **Processing**: box "Audio
processing" renamed "AGC" (dropdown + status line) and box "Mode". **Presets**: box "Presets". **Parameters**: boxes Leveler, Compressor, Limiter
and, depending on the mode, Live meters or Speakers (live). **Per-user**: box "Per-user settings". The tab
bar's right side shows a live summary (`statusBits(true)`: mode or "Vanilla AGC" / "Vanilla AGC (experimental)", preset (or "custom values"), added delay); the card on the
overview shows the short form (`register.status`). Footer: "Edits apply live and survive a restart." + **Reset to Voice** (applies the
Voice preset) + **Save as preset…** (switches to Presets and opens the name field). Parameter help texts are hover tooltips (the "?" mark).
Without the native module only the note above the tabs and the AGC dropdown box are shown (the stock keys work without it). While a Vanilla choice is selected the
mode/preset/parameter/meter boxes are dimmed (still editable).

- **AGC** box (Processing tab): the dropdown (help text, live stock state), **Mode** pills (whole stream / per speaker, help text under them), a status line
  (processing/passthrough, delay, speakers, hook state).
- **Presets**: pills for the built-ins and your own; "modified" badge when the current values differ from the selected preset
  (tolerance 0.006); buttons Save as..., Update preset (own preset, modified), Rename, Delete, Revert to preset. Own presets are in the
  mod's storage as `{id: {name, values}}`; the native `preset` key is `user_<id>` (the native parser only takes `[A-Za-z0-9_-]`, free-text
  names cannot go there). Deleting the selected preset sets `preset:"custom"`.
- **Parameters** (each: slider + number field + unit, help as hover tooltip; ranges = the DSP's): Leveler (target, max boost, noise gate),
  Compressor (on/off switch at the top of its box, off by default; while off its sliders stay visible but dimmed and locked; then threshold, ratio, knee, attack, release, make-up), Limiter (lookahead, ceiling). `PARAMS` in `index.js`.
- **Live meters**: whole mode: input level, gain reduction, leveler gain, input/output peak (`/meters`, 120 ms). Per-speaker mode: a list
  of known speakers with nickname (client id -> nickname through `api.peers.list`), level, gain reduction, leveler gain, an "override"
  badge, idle ones dimmed, and an "Audio..." button (`/speakers`, 120 ms). Polling runs in the settings scope only: it stops when the
  page is left, the mod is switched off, or the window is hidden.
- **Per-user settings**: users in your channel plus every user with saved settings (summary, Edit..., Forget).
- **TeamSpeak playback AGC**: driven by the AGC dropdown, see above (mechanics in [ts6-modding-surface.md](ts6-modding-surface.md)).

### Preset values

| | target | max boost | gate | compressor | threshold | ratio | knee | attack | release | make-up | lookahead | ceiling |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| **Voice** (= DSP defaults) | -32 dB | 12 dB | -60 dB | off | -24 dB | 1:1 | 6 dB | 5 ms | 150 ms | 4 dB | 5 ms | -12 dB |
| **Music** | -18 dB | 6 dB | -60 dB | off | -18 dB | 2:1 | 12 dB | 20 ms | 400 ms | 2 dB | 5 ms | -1 dB |
| **Quiet night** | -26 dB | 18 dB | -55 dB | off | -30 dB | 6:1 | 6 dB | 2 ms | 120 ms | 0 dB | 8 ms | -6 dB |

The compressor columns are the values it takes when switched on; with it off they have no effect (make-up included).
Leveler targets/boosts are unchanged: speech at RMS -20 dBFS with the limiter at -1 dB is already loud, and the peaks the leveler
leaves are caught by the limiter alone (the gain reduction meter then shows the limiter only). Loudness drops by the old make-up
(about 4 dB on Voice, 2 dB on Music) minus what the compressor used to take off the peaks; raise "Target level" if you want it louder.

Voice: everyday speech. Music: music bots; a gentle leveler (small boost), low ratio, wide knee, slow attack/release so dynamics survive and
only peaks are stopped. Quiet night: low overall volume (target -26, ceiling -6 dB), strong peak control (ratio 6, fast attack, more boost so
whispers stay audible, a little more lookahead). `PRESETS` in `index.js`. The old Gentle/Balanced/Strong + strength slider were dropped
(three anchors blended by one slider were less transparent than named presets plus the real parameters).

## Compressor switch

`comp_enabled` (`ts6dsp_params`, `native/dsp/ts6dsp.c:ts6dsp_process_f32`): off = the compressor adds no gain reduction **and no make-up**
(make-up is part of the compressor stage and ramps to 0 in 10 ms; leftover reduction decays with the release time), so leveler and
limiter are the only active stages. Exposed as `comp_enabled` in `/config` and persisted in `agc.json`. Per-user custom parameters do not
include it: the switch follows the global setting.

- **Default off**, including the native default (so the native default values still equal Voice and the value-match fallback
  highlights Voice on a fresh install). Built-in presets all carry `comp_enabled:false`.
- **Migration:** an `agc.json` without the field loads as off, so existing installs lose the compressor on the next client start
  (native change: restart needed). Their other values are kept. Why: the user wants leveler + limiter only; keeping old configs
  "on" would leave the problem in place for exactly the people who have it.
- **User presets** saved before the switch have no field: they are treated as compressor **on** (they keep what they were made with);
  handled in `presetValues`/`same` of `panel/mods/audio/index.js`, no storage rewrite.
- Ratio 1 is **not** used as a bypass: make-up would still raise the level, hence a real switch.

Why (off by default): the compressor with make-up gain and a fast release lifts room-reverb tails between syllables, which some
microphones turn into an audible slight echo. The user's decision: leveler and limiter are the only things really active; the
compressor stays available as an opt-in.

## Per-user audio ("Audio..." popover)

Entry points: right-click a user in the channel tree -> "Audio..." (`api.contextMenu.client`, section "Mods"), or Edit... in the
page's per-user list. Both end in `openUser` (`api.modal.show`). Contents:

- **Volume**: TeamSpeak's own per-user volume (`setClientVolumeModifier`, stock range up to +10 dB; slider -40..+10), applied session-only
  (`persist=false`) so the client's own saved value is untouched; the mod remembers it per UID and restores the original on switch-off.
- **Mute**: the stock local mute (`requestSetClientsMute`), set only if the user was not already muted, lifted again by Reset / mod off.
- **Boost** 0..+24 dB: native `gain_db` after the processing, clamped to the ceiling (the point of the per-speaker hook: it sits before the
  stock volume multiply, so this goes past the stock cap).
- **AGC for this user**: Global settings / Bypass (`enabled:false`) / Custom: tick the parameters this user gets their own value for
  (everything except `lookahead_ms`: one delay-line length for all speakers); unticked ones follow the global settings.
- **Live** (per-speaker mode): the user's level, gain reduction, leveler gain, "override active"; a hint with a switch button when boost/
  bypass/custom cannot act (not per-speaker mode or not TS6Mods).
- Reset everything for this user, Done.

**Persistence (UID rule).** Records are stored by **UID** in the mod's storage (`users`: `{uid: {name, vol?, mute?, boost?, agc?, params?}}`;
a record equal to "nothing changed" is removed). Client ids are per session and the native overrides are keyed by client id, so
`syncPeers` pushes `{client_id -> override}` (and volume/mute) for every user present, on roster events (`api.peers.onChange`: moves,
connection changes, property updates, 300 ms debounce) and every 3 s as a safety net: that covers connect, join, reconnect and a client
restart. A user who left gets a `null` override (a re-used id must not inherit it). Switching the mod off undoes all of it (volume back to
the original, mute lifted, overrides cleared). Why UID and not the native side: the native module cannot know identities.

## Known limits

- Pulse backend only; updating the client may change how libpulse is loaded or move the per-speaker hook signature
  ([per-speaker-hook.md](per-speaker-hook.md), "What to do when the signature no longer matches"): with no match the module stays pure
  passthrough and the page says "hook not installed".
- Whole mode: all speakers share one gain. Sound volume applied by the OS stream comes after the processing; wave-file sounds are 20 dB lower.
- Toggle click, 1 MiB buffer limit, `lookahead_ms` applied on (re)create (a change re-creates the state).
- Per-speaker mode: 48 kHz mono blocks, 32 simultaneous speakers, one shared lookahead, `/speakers` reports `schid` 0 (matched by client id).
- Per-user boost/bypass/custom need per-speaker mode and the AGC set to TS6Mods; volume and mute work in both modes. The stock volume value set
  with `persist=false` cannot be read back (the getter shows the saved value), so the mod keeps its own copy.
- The panel reaches the module through the CDP injector; if it dies the page shows "not loaded" while audio keeps the last saved config.
- Presets/user records/AGC choice live in the mods blob (profile database), the DSP values in `agc.json`; wiping one without the other shows
  "custom" values or an empty preset list.

Why (disable/enable): `disable()` in `panel/mods/audio/index.js` sends ONE `/config` post (pending changes merged with `enabled:false`) at
once and keeps its promise (`offPost`); `enable()` awaits it before reading `/config`. Two chained posts left a request in flight after
the switch-off (a vanilla-check flake: "native polling continues"), and a quick off->on read `/config` before the post landed and lost
the AGC choice. The debounced save and `refreshStatus` also stop touching state once the mod is disabled.
Preset selection: an unknown native `preset` name (the native default is the legacy "balanced") selects the built-in preset whose values
equal the current ones (`selected()`), so a fresh install shows Voice instead of "custom".

## Why

- **dlsym interposition:** libpulse is `dlopen`ed, so a plain preload definition of `pa_stream_write` is bypassed; returning wrappers from
  `dlsym` is the only point that sees every lookup. `RTLD_NEXT` lookups are forwarded by tail call so interposers elsewhere keep working.
- **Hook at `pa_stream_write` (whole mode):** the client's mixer and the stock WebRTC AGC are inside a stripped, statically linked core; the
  output write needs no offsets and survives updates as long as libpulse is used. Per-speaker mode needs the inline hook for exactly that reason.
- **CDP + injected JS:** the stock binary verifies its UI bundle, so edited UI files are rejected; one extra launch flag (loopback only) lets us
  add UI without patching anything.
- **A CDP binding as the page's route to the module:** the stock UI page cannot open `http://` connections at all
  (`net::ERR_UNKNOWN_URL_SCHEME`, also for WebSocket/XHR/images), so the injector proxies the allowed endpoints via `Runtime.addBinding`.
  The page is a thin client of the loopback API and the injector must keep running.
- **Default off:** a client with everything disabled behaves like vanilla; see the vanilla rule for how the mod switch and the native switch are tied.
- **Native config file for the DSP values, mods blob for presets/users:** the hook must obey the DSP values at start-up before any UI exists
  and the client's own profile stays untouched by it; presets and per-UID records are UI data.
- **Unsetting nothing in `LD_PRELOAD`:** the first client process re-spawns itself; dropping the variable there would lose the mod. The
  `--type=` filter is the guard instead.
- **Chain order leveler -> compressor -> limiter:** see [native/dsp/README.md](../../native/dsp/README.md).
- **Loopback listener hardening:** Origin/Host checks because any web page can otherwise fire requests at loopback.
- **Mode is one switch, not two mods:** whole and per-speaker are mutually exclusive in the native module (per-speaker supersedes the whole-mix
  path, which would otherwise double-process), so the page offers them as one choice sharing the same parameters.
